# Radar Publication UI

## Scope

Radar UI v1 is a presentation-only layer on top of the existing publication contract. It does not change fare discovery, ranking, historical comparison, coverage semantics, publication refs, or the immutable-history model.

The static site remains generated by `cheap_flight_radar.publication` with no client-side framework, JavaScript runtime, external stylesheet, CDN dependency, or separate presentation service. The same deterministic inputs must continue to produce the same HTML bytes.

## Information hierarchy

The page is deliberately organized in three levels.

### 1. Top signals

The four SSOT user-facing views are the first and strongest visual layer:

- Absolute Cheapest;
- Near-Term Cheapest;
- Best Short Break;
- Unusual Long-Haul Deal.

Each view is a large card with route, effective trip price, travel dates, trip/verification state, and compact historical context. Price is the dominant typographic element. A missing view remains an explicit empty state rather than being replaced by another score winner.

### 2. Market radar

Japan, Korea, China, and World retain dedicated sections. Their candidate cards are intentionally more compact than the four top views so market breadth is visible without competing with the primary price-first decisions.

### 3. Operational evidence

Origin coverage, fixed-watch freshness, and China-mode coverage are summarized near the top as status badges and expanded near the bottom as a complete operational panel.

Failed/non-converged cheap seeds and run notes remain durable report content, but they are secondary diagnostics and are collapsed with native HTML `<details>` elements by default.

## Historical metrics

The UI only renders values already allowed by `flight-radar.yaml` and `docs/price-history.md`.

Candidate cards may show:

- comparable sample count and confidence;
- prior comparable all-time low;
- configured rolling lows when available;
- selected recent median baseline and its actual window;
- percent below/above that baseline when defined;
- empirical historical percentile only after the SSOT sample threshold is met;
- sparse-history wording for none/sparse/low confidence;
- an anomaly label when the historical engine emits one.

Dense historical evidence is available under a native disclosure control so the concise visual summary never hides the exact underlying values used by the previous report format.

## Status color semantics

Color is supportive rather than authoritative. The text state is always present.

- green: complete/revalidated/attempted or medium/high confidence;
- amber: partial, due, sparse/low confidence, or non-converged states;
- red: incomplete/failed/error states;
- gray: states that do not map safely to the above groups.

Price delta uses green only when the current price is below the selected recent baseline. A price above baseline uses amber. No color alone creates a new deal or anomaly classification.

## Responsive behavior

Desktop uses two-column top-view and market grids. At the mobile breakpoint the layout becomes a single column, coverage panels stack, and run-index links stop forcing date metadata onto the same line.

The site uses system fonts and native HTML controls. It respects reduced-motion preference and requires no JavaScript for navigation, historical details, or diagnostic disclosure.

## Root index

The root page is a publication dashboard rather than an unstyled file list. It presents the latest run as the primary action and preserves direct links to every permanent per-run page.

`/latest/` remains byte-identical to the newest permanent run page. Presentation changes therefore affect both through the same generator instead of introducing separate latest-page logic.

## Deterministic UI gate

Fixture tests assert that:

- the four top-view cards and coverage strip exist;
- market sections use the compact hierarchy;
- historical evidence details and diagnostic disclosures remain present;
- mobile CSS is emitted;
- no external JavaScript or stylesheet is introduced;
- the root index links both latest and the permanent run;
- `/latest/` remains byte-identical to the permanent newest run.

The existing publication tests continue to gate required headings/content, historical percentile thresholds, future-history immutability, Best Value removal, and coverage/freshness evidence.
